## V2 scoped retry checkpoint — 2026-11-15

The reference backend advertises `ui.retryBinding` for executable partial snapshots. The shell exposes a retry button for a failed binding; retry executes only that source, keeps the other committed results, revalidates component semantics and all authorization scopes, and commits a new generation atomically. Failed or cancelled retries retain the previous snapshot. Retry requests use the existing event, replay, idempotency and optimistic-conflict paths; completed responses regain eligible scoped controls. Imported read-only snapshots do not acquire retry automatically.

Integration coverage checks a failed retry, successful recovery, unchanged successful-source execution count, duplicate replay, stale generation, restart and authorization revocation. ## V2 scoped controls checkpoint — 2026-11-15

Added registered, versioned option resolvers and an in-memory control coordinator. The host explicitly enables controls for executable responses; static imported snapshots remain read-only. Within-answer select, multi-select and date-range updates validate the control schema and selected options, recheck authorization, recompute datasets and facts, and commit a new generation only after an optimistic concurrency check.
